# Строгий анализ методов в публикациях о вирусах

Дата снимка: **15 сентября 2026 года**. Основная единица счёта — уникальный **PMID**.

## Что изменено относительно исходной картинки

Исходный запрос `virology[All Fields]` зависел от Automatic Term Mapping PubMed и от полноты/способа MeSH-индексации. Новый анализ разделяет отбор корпуса и разметку методов:

1. **Основной корпус `text_only`** — фиксированный словарь вирусных терминов с явным тегом `[Title/Abstract]`. Временные ряды и ранги на основных графиках строятся только по нему.
2. **Контур `explicit_mesh`** — явные рубрики `Viruses[MeSH Terms]` и `Virus Diseases[MeSH Terms]`. Он не смешивается с основным корпусом и используется для анализа чувствительности.
3. **`mesh_only`** — часть MeSH-контура, которая не вошла в `text_only`. Именно её доля особенно чувствительна к изменениям индексирования.
4. **`expanded_union`** — объединение двух контуров после дедупликации по PMID; хранится для проверки полноты, но не служит знаменателем основного графика.

Точные 67 текстовых терминов, дата среза и правила включения находятся в `pubmed_virus_corpus_definition_v1.json`. Скрытое расширение `[All Fields]` не используется.

## Правила датировки и YTD

Каждый PMID получает одну дату по фиксированному приоритету:

1. электронная `ArticleDate`;
2. другая `ArticleDate`;
3. `JournalIssue/PubDate`;
4. дата `pubmed` из истории записи;
5. год из `MedlineDate`.

Основной обзорный график содержит полные годы **2010–2025** и явно помеченную предварительную точку **2026†** по всем доступным на дату снимка записям. Последний сегмент показан пунктиром и выделен фоном. Отдельный matched-YTD график использует одно окно для всех лет: **1 января — 15 сентября включительно**. Записи только с годом исключаются из YTD; записи с месяцем, но без дня, включаются для января–августа и консервативно исключаются для сентября.

## Разметка методов

Совпадения ищутся локально, без новых сетевых запросов, в объединении `ArticleTitle + AbstractText`. 34 обзорные категории и семь AI-подкатегорий пересекаются: одна статья может входить в несколько категорий. Ранг показывает частоту упоминаний среди этих 34 категорий, а не качество или зрелость метода.

Записи без абстракта остаются в знаменателе и могут совпасть по заголовку. Покрытие абстрактами и доля неполных дат публикуются в таблице качества.

## Воспроизведение

```bash
python scripts/build_strict_pubmed_corpus.py --target corpus
python scripts/analyze_strict_pubmed_methods.py --recount --output-dir results
```

Загрузчик сохраняет gzip-страницы, число записей, исходный запрос и SHA-256 каждой страницы в `source_manifest.csv`. Прерванный запуск возобновляется с проверки уже сохранённых частей. Объединённый XML и таблица принадлежности корпусам также получают SHA-256.

Источник данных: [NCBI PubMed](https://pubmed.ncbi.nlm.nih.gov/) через [Entrez E-Utilities](https://www.ncbi.nlm.nih.gov/books/NBK25501/). Архив содержит библиографические XML-записи и абстракты, предоставленные PubMed, но не издательские PDF и не полный текст статей.

## Фактический размер снимка

Сборка завершена без расхождений с контрольными счётчиками PubMed: 1 447 899 уникальных PMID в `text_only`, 953 464 в явном MeSH, 878 566 в пересечении и 1 522 797 в объединении. Абстракт присутствует у 1 359 499 записей (89,28%). Полный XML не хранится в GitHub из-за размера; скрипт воспроизводит его локально в каталоге, указанном через `--target`.

Интерпретация ключевых трендов и точные значения приведены в `STRICT_FINDINGS_RU.md`; исходные годовые числа находятся в `strict_virology_method_counts.tsv`.
